# 간결함 리뷰

이번 변경이 필요한 만큼만 커졌는지 본다. 고치기 전에 찾은 것을 먼저 보여 주고 허락을 받는다.

## 순서

1. 변경 범위를 본다: `git diff --stat`과 `git diff`(커밋 전이면 `git diff HEAD`).
2. 바뀐 부분마다 아래 질문에 답한다. 해당하는 것만 적는다.
   - **지울 수 있나?** 쓰지 않는 함수·변수·인자, 한 번만 쓰는 감싸기 함수, 주석 처리된 코드
   - **이미 있는 것을 다시 만들었나?** 같은 일을 하는 함수나 라이브러리 기능이 이미 있는지 찾아본다
   - **덧댄 예외인가?** 실제로 일어나지 않는 경우를 막는 조건, 원인 대신 증상을 막는 `if`, 삼킨 예외
   - **덧댄 자리인가?** 같은 뿌리의 문제를 한 번에 풀었는지, 또 한 곳에 덧댔는지 본다.
     이 자리를 최근에 여러 번 고쳤으면(`git log -- <파일>`) 원인과 구조를 먼저 본다
   - **읽히나?** 한 줄에 여러 일, 세 겹이 넘는 중첩, 하는 일을 말하지 않는 이름
   - **범위 밖인가?** 요청과 관계없는 정리·리팩터링
   - **테스트가 동작을 보나?** 구현을 그대로 베낀 테스트, 아무것도 확인하지 않는 테스트
3. 결과를 짧은 표로 보여 준다: 파일:줄, 무엇을, 왜, 줄어드는 줄 수.
4. 사용자가 고른 것만 고친다. 고친 뒤 테스트와 `node harness/check.mjs <바꾼 파일>`을 다시 돌린다.

## 하지 않는 것

- 찾은 것을 허락 없이 고치지 않는다.
- 이번 변경과 관계없는 오래된 코드를 다시 쓰자고 하지 않는다. 눈에 띄면 따로 적어만 둔다.
- 줄 수를 줄이려고 여러 일을 한 줄에 몰아 쓰지 않는다. 읽히는 것이 목표다.
